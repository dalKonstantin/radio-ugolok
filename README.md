# Radio Ugolok

Внутреннее офисное веб-радио: один общий эфир, который все слушают в наушниках синхронно.

Готовы все четыре этапа: синхронизация (M1), библиотека и загрузка (M2), эфир с очередью,
скипом и чатом (M3), интерфейс в стиле SoundCloud с waveform (M4).

## Запуск

Через Docker — нужен только Docker:

```sh
make up           # = docker compose up -d --build; http://<сервер>:8080, данные в ./data
make logs         # логи; make down — остановить
```

Порт, каталог данных и настройки меняются переменными в `.env` или окружении:
`RADIO_PORT`, `RADIO_DATA_DIR`, `RADIO_MAX_UPLOAD`, `RADIO_BITRATE`, `RADIO_QUEUE_LIMIT`,
`RADIO_EPHEMERAL`.

Без Docker нужны Go 1.23+ и `ffmpeg`/`ffprobe` в PATH:

```sh
make run          # http://localhost:8080, только с этой машины
make build        # один бинарник bin/radio; на сервере: ./radio -addr :8080
```

Флаги (или переменные окружения `RADIO_*`):

| Флаг | По умолчанию | Смысл |
| --- | --- | --- |
| `-addr` | `:8080` | Адрес прослушивания |
| `-data` | `./data` | Корень хранилища |
| `-max-upload` | `150` | Лимит загрузки, МБ |
| `-bitrate` | `192` | Битрейт эфирного mp3, kbps |
| `-queue-limit` | `3` | Позиций в очереди на одного человека |
| `-ephemeral` | выключен | Удалять трек через 5 секунд после проигрывания |

## Загрузка

Кнопка «Загрузить трек», перетаскивание файлов в окно или `POST /api/upload`
(multipart, поле `file`, необязательное `nick`).
Формат определяется по содержимому через `ffprobe`: mp3, flac, wav, aiff, ogg Vorbis, opus,
m4a (AAC/ALAC), wma. Всё перекодируется в эфирный MP3 CBR 44,1 кГц стерео и кладётся в
`data/tracks/<sha256 исходника>.mp3`; исходник не хранится. Тот же файл второй раз не
создаёт дубль. Теги и обложка читаются из оригинала, обложка — `data/covers/<id>.jpg`
до 500×500, пики waveform (1000 байт) — в SQLite `data/radio.db`.

```sh
curl -F nick=kostya -F file=@song.flac localhost:8080/api/upload
curl 'localhost:8080/api/library?q=город'
```

## Эфир

Играет только то, что поставили в очередь; пустая очередь — тишина. Трек сменяется сам
через длительность + 0,5 с. Скип — голоса больше половины слушателей (минимум два, один
слушатель скипает сам). Удалить из библиотеки можно трек, который уже звучал, но не
играющий сейчас. Очередь, голоса и чат (последние 200 сообщений) живут в памяти:
после перезапуска эфир молчит с пустой очередью, библиотека остаётся.

## Интерфейс

При открытии страницы — оверлей с кнопкой: без клика браузер звук не даст. Перемотки и
паузы эфира нет: waveform не кликабельна, «Отключиться» глушит звук только у себя, а
«Подключиться» возвращает в текущую точку эфира. Громкость локальная. От 1280 px чат —
третья колонка, уже — выезжающая панель по кнопке «Чат» в шапке; от 1000 px очередь и
библиотека стоят рядом, уже — одной колонкой. Блок диагностики — в правом нижнем углу.

## Как работает синхронизация

Сервер не стримит аудио: он рассылает по WebSocket, какой трек играет и с какой серверной
отметки времени (`startedAt`). Клиент оценивает сдвиг своих часов относительно сервера —
10 обменов ping/pong, медиана трёх с наименьшим RTT, повтор раз в минуту. Позиция эфира —
`(Date.now() + offset - startedAt) / 1000`; клиент перематывает `<audio>` в неё с запасом
0,3 с и запускает воспроизведение, когда эфир догонит запас. Дальше на каждом `timeupdate`
он меряет дрейф: до 50 мс ничего не делает, до 1 с подстраивает `playbackRate` в пределах
±2 %, больше — перематывается жёстко. Сам файл едет обычным HTTP с `Range` и кешируется навсегда.

## Проверка

```sh
make test         # go vet, go test (автомат эфира, библиотека), node --test (offset, дрейф)
```

Вживую: открыть страницу на двух машинах или в двух разных браузерах, загрузить трек,
поставить его в очередь, нажать «Подключиться» в обоих — звук в унисон, `drift` в блоке
диагностики держится в пределах ±50 мс. Искусственный дрейф из консоли:
`radio.audio.currentTime += 3` — должен выправиться сам. Для проверки на слух удобен метроном:

```sh
ffmpeg -f lavfi -i "aevalsrc=exprs='sin(2*PI*if(lt(mod(t,4),1),1760,880)*t)*exp(-25*mod(t,1))*0.6':d=180" metronome.wav
```
